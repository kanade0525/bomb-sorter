# YouTube ゲームルーム（Playables）への応募手順

応募フォームに貼る文面そのものは英語の
[`youtube-playables.md`](youtube-playables.md) にある。こちらは**人が手を動かす順番**だけを書いたもの。

公開されている情報は「興味登録フォームを出す」ところまでで、その先（審査の基準、
提出物の形式、所要期間）は Google から返事が来るまで分からない。ここに書いていないことは、
**調べても出てこなかったことであって、省略したことではない**。

---

## 前提

| 要るもの                     | 状況                                                                   |
| ---------------------------- | ---------------------------------------------------------------------- |
| Google アカウント            | フォームが Google フォームなので必要                                   |
| 遊べる URL                   | ある → https://kanade0525.github.io/bomb-sorter/                       |
| 完成したゲーム               | ある。フォームに「構想段階のものは出すな」と明記されている             |
| YouTube チャンネル・法人登録 | 公開情報では必須と書かれていない。会社として出すなら社名を書く欄がある |

費用はかからない。登録料のたぐいも無い。

---

## 1. 出す前に手元で通すこと

```bash
npm run verify           # check → build → e2e。落ちているものを出さない
npm run check:playables  # ゲームルーム向けビルドを認定要件と突き合わせる
```

**`npm run check:playables` が通ることと、応募に受かることは別**。あの検査が見ているのは
機械で見られる要件（絶対パス、容量、SDK の読み込み順、Service Worker の混入など）だけで、
面白さ・権利・運営方針は人が見る。

### 資料の数値を突き合わせる

`youtube-playables.md` に書いてある容量とファイル数は **2026 年 10 月 1 日時点の実測**
（単体配布 537.7 KiB / 18 ファイル、ゲームルーム向け 62.1 KiB / 3 ファイル）。

**ビルドを変えたら、出す前にここを必ず取り直すこと。** 数値は
`npm run check:playables` の出力にそのまま出る。

一度、ビルドを絞ったのに資料が「84 KiB・9 ファイル」のまま取り残されていた。
実装をなぞって書いた数値は、実装を変えたら一緒に直さないと腐る。

## 2. フォームを出す

**Playables interest form**（興味登録フォーム）

<https://docs.google.com/forms/d/e/1FAIpQLSdvdQ0lgIq2369aemj1O6w8R8FwGn9O5ARRGODDDUbVINCRJQ/viewform>

入口は [developers.google.com/youtube/gaming/playables](https://developers.google.com/youtube/gaming/playables)
にある「Playables interest form」のリンク。**フォームの URL は向こうの都合で変わりうるので、
開く前にこのリンクから辿り直すこと。**

### 何を聞かれたら、どこを貼るか

フォームの設問は向こうが随時変える。設問文そのままの対応表ではなく、
**聞かれる内容ごとに、英語の資料のどこを引けばいいか**を並べてある。

| 聞かれること                | 資料の場所          | 中身                                                       |
| --------------------------- | ------------------- | ---------------------------------------------------------- |
| ゲーム名                    | 冒頭の表            | Bomb Sorter                                                |
| 遊べる URL                  | 冒頭の表            | GitHub Pages の URL                                        |
| 一言説明                    | §1 One line         | 1 行                                                       |
| 短い紹介（50 語程度）       | §1 Short            | そのまま貼れる                                             |
| 長い紹介（150 語程度）      | §1 Long             | そのまま貼れる                                             |
| ジャンル / 1 回の長さ       | 冒頭の表            | アーケード / 30 秒〜数分                                   |
| なぜ Playables 向きか       | §2                  | 短時間・縦横両対応・インストール不要                       |
| 技術構成・容量・性能        | §3                  | 実測値つき。ビルドを変えたら取り直す                       |
| 要件を満たしているか        | §4                  | 要件ごとの対応表                                           |
| 権利関係                    | §5                  | 完全オリジナル、素材の同梱なし、MIT                        |
| スクリーンショット          | §6 / `screenshots/` | 9 枚（縦持ち・横持ち・タイトル・プレイ中・ゲームオーバー） |
| どこで Playables を知ったか | §7                  | AI（ChatGPT、Gemini 等）                                   |
| 会社名・連絡先              | —                   | ビッグゲートとして出すか個人として出すかを決めてから書く   |

**連絡先に使うメールアドレスは、返事を確実に受け取れるものにすること。**
応募後のやり取りはすべてそこへ届く。

### スクリーンショットの渡し方

`docs/submission/screenshots/` の 9 枚。フォームがファイル添付を受け付けない場合は、
GitHub のリポジトリが公開なので、そのディレクトリの URL を貼れば足りる。

---

## 3. 出したあと

- 返事が来るまでは待つしかない。所要期間は公開されていない
- **その間もゲームを触ってよい**。URL は固定なので、更新しても応募内容は腐らない
- 承認された場合、開発者向けポータルと詳しい提出手順が案内される見込み。
  その段階で `npm run build:playables` の成果物（`dist-playables/`、3 ファイル・62 KiB）を
  指定の形で渡すことになる

### 断られた場合

itch.io など、審査の緩い場へ出す道がある（`npm run package:itch`）。
Playables 向けに作ったものは無駄にならない。SDK の有無以外は同じビルドで、
違いは [`src/platform/host.ts`](../../src/platform/host.ts) の一枚に閉じてある。

---

## 覚えておくこと

- **公開されている認定要件は、応募フォームとは別物**。要件は「受かったあと守るもの」で、
  フォームは「見てもらうための入口」
- `npm run check:playables` は実装が要件から外れたときに落ちる。**ビルドを変えたら必ず走らせる**
- フォームに貼る数値は、必ず `npm run check:playables` の出力から取る。手で書いた数値は腐る
